# Task 4 — Spring Service Template

The template lives under
`platform/starters/platform-spring-boot-starter/` and the per-service
overlays under `services/<service>/`. Every service must consume the
template via the BOM at `platform/starters/bom/pom.xml`.

## 4.1 Hexagonal structure

```
Inbound Adapter  → Application Port → Domain → Outbound Port → Adapter
```

- Domain code is framework-free; the ArchUnit test in every service
  rejects `org.springframework..` and `jakarta.persistence..`
  references inside `..domain..`.
- Spring MVC, gRPC, and Kafka adapters are isolated under
  `adapter/in/`.
- Persistence, event publication, and external-system clients are
  isolated under `adapter/out/`.

## 4.2 Cross-cutting primitives

The platform starter provides:

- **Validation** — `spring-boot-starter-validation` + Jakarta
  `@Valid` on every controller.
- **Idempotency** — `JdbcIdempotencyStore` keyed by
  `Idempotency-Key`; conflicting payload hashes return 409.
- **Local audit + outbox** — `OutboxIdentityEventPublisher` (and the
  equivalent in each service) writes the audit row and the outbox
  row in the same transaction as the aggregate mutation.
- **Inbox / deduplication** — `JdbcInboxStore` + `KafkaConsumerConfig.shouldProcess`.
- **Retry / DLQ** — `DefaultErrorHandler` with 3 retries and
  `<topic>.dlq` recoverer.
- **Replay** — operators reset the consumer group offset and the
  inbox dedup state.
- **Owning-service Saga state machine** — no external workflow
  engine. The state machine is in the application layer of the
  owning service.

## 4.3 Deadline-bound defaults

- gRPC server keeps a 30s keepalive and a 5s timeout.
- gRPC client interceptor (`TracingClientInterceptor`) propagates
  correlation/causation/operation headers.
- Synchronous calls may not exceed 2 hops (design.md).

## 4.4 Data layer

- **Flyway** migrations are the schema authority.
  `services/identity-service/src/main/resources/db/migration/`
  contains V1 + V2 migrations.
- **Spring Data JDBC** persists aggregates through the domain
  repository.
- **jOOQ** is used for explicit SQL and projection queries; the
  generator runs against the migrated schema. The reference
  generator config lives at
  `platform/ci/flyway-jooq-testcontainers.sh` and the per-service
  config is generated by the bootstrap script.
- **Testcontainers** brings up `mysql:8.4` for integration tests.

## 4.5 Architecture tests

Every service has an ArchUnit test under
`src/test/java/<pkg>/archunit/ArchitectureTest.java` that enforces:

- `domain` does not depend on Spring or JPA.
- No service may depend on another service's package.
- No synchronous call cycles.
- The Hexagonal layer ordering.

The repository-wide scanners under
`tooling/architecture-scan/` reject root reactors, cross-service
imports, and forbidden patterns at the file level.

## 4.6 Versioned contracts

- OpenAPI contracts: `contracts/api/v2/openapi.yaml`.
- Event Protobuf schemas: `contracts/events/**/*.proto`.
- gRPC Protobuf schemas: `contracts/grpc/**/*.proto`.
- Each contract has its own versioning and publication lifecycle
  (ADR-010). Generated artifacts are transport-only; domain models
  remain in the owning service.

## Acceptance

- `mvn -B -ntp -pl services/identity-service -am package` succeeds
  with the BOM and starter artifacts in the local Maven cache.
- The ArchUnit test passes.
- The `OutboxRelay` publishes staged events with the required
  metadata headers; `KafkaConsumerConfig.shouldProcess` dedupes.
- `tooling/architecture-scan` exits 0 on the monorepo.
